# Integração Windows — checkpoint RUMO 1.8

O processo Tauri cria um tray nativo com **Abrir RUMO**, **Quick Add**, comandos de Focus, sincronização Google e **Sair**. O plugin oficial `single-instance` tenta restaurar e focar a janela existente quando outro lançamento ocorre. `autostart` é desativado por padrão e usa o mecanismo oficial do plugin; `--rumo-autostart` permite esconder a janela ainda no setup nativo quando a preferência local `windows_start_minimized` está ativa. O atalho global opcional usa o plugin oficial de global shortcut. O atalho interno Ctrl + Espaço e Ctrl + K permanecem independentes. Se o Quick Add global abrir uma janela que estava no tray, ela retorna ao tray ao fechar a captura. O menu do tray só abre a janela existente; não cria uma segunda instância lógica.

**Ao fechar:** o comportamento antigo, encerrar, permanece padrão para não manter um processo residente sem aviso. O usuário pode escolher fechar para a bandeja em Configurações → Windows. Nesse caso o WebView fica vivo e os trabalhos locais continuam; a primeira ocultação explica isso uma única vez. O menu **Sair** suspende workers, aguarda flush de Thoughts e séries, pausa a sessão Focus, fecha o pool SQLite e encerra o processo. Com o processo realmente encerrado, não há notificações nem sync em background. Os controles de Focus do tray usam o mesmo repositório de sessões; não criam outro relógio.

`startBackgroundScheduler` reúne uma verificação local a cada 60 segundos para notificações e automações, e uma cadência de 5 minutos para Google Agenda, respeitando as próprias travas de reentrada de cada worker. Uma escrita local no calendário faz debounce de 800 ms para o Google. Os identificadores de entrega de notificação já persistem no SQLite e previnem repetição; a política existente aceita apenas lembretes atrasados em menos de dois minutos, evitando uma enxurrada após horas desligado. A opção de notificação na bandeja pode ser desativada. Open Finance **não** possui worker de rede, pois não há provider live seguro configurado.

**Estado de validação:** os testes de aplicação verificam o scheduler em janela visível e oculta, sem criar serviço Windows. A compilação Rust/Tauri e o smoke nativo desta integração permanecem pendentes: `cargo check` de 02/10/2026 parou ao carregar `phf_macros-...dll` com Windows Application Control, erro **4551**, dentro dos build scripts de `tauri-plugin-autostart` e `tauri-plugin-global-shortcut`. Isso ocorreu antes da checagem do módulo Rust do RUMO. Nenhuma proteção foi desativada ou contornada. Tray, single instance, startup, hotkey global e Focus via tray ainda **não foram comprovados no runtime Windows**; precisam de validação em ambiente que permita a execução legítima da toolchain e do aplicativo.

Referências de implementação: [tray](https://v2.tauri.app/learn/system-tray/), [single instance](https://v2.tauri.app/plugin/single-instance/), [autostart](https://v2.tauri.app/plugin/autostart/), [global shortcut](https://v2.tauri.app/plugin/global-shortcut/).

## Open Finance na continuidade da 1.8

O scheduler existente agora acorda o worker Open Finance a cada cinco minutos. Ele só faz importação se a instalação estiver emparelhada, a preferência não for manual e houver conexão/conta local vinculada com dados vencidos (seis horas) ou marcada como atualizada por webhook. A preferência em Finanças → Contas conectadas permite somente manual, ao abrir ou ao abrir + seis horas. A trava em memória impede dois syncs locais concorrentes para a mesma conexão. O ciclo persiste enquanto a janela estiver no tray e para em **Sair**. Sem gateway/rede, o erro é contido e Finance local abre normalmente. Ainda não foi validado no runtime Windows devido ao bloqueio nativo 4551.
