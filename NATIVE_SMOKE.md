# Smoke nativo isolado (Windows)

O workflow manual `Windows isolated native smoke build` produz somente `RUMO-Smoke.exe` e um manifesto. O overlay `src-tauri/validation.native.conf.json` define `com.rumo.validation.native.v180` e `RUMO Smoke`; a configuração de produção permanece `com.rumo.desktop`. O build de smoke fixa os namespaces de credenciais `RUMO-Smoke-v180` e de autostart `RUMO Smoke Validation`. A chave de instância única e a identidade das notificações devem ser confirmadas no runtime. Não há instalador ou release desse perfil.

O SQLite, attachments, backups e configurações do smoke usam `app_config_dir` derivado do identifier de smoke. O preflight compara o hash do executável com o SHA-256 **copiado separadamente do log da CI**, inspeciona o identifier embutido, recusa o identifier e o hash conhecidos de produção, confirma o identifier via IPC e exige que `data_info` aponte para o diretório de smoke e que `integrity_check` retorne `ok`. O script não abre o `rumo.exe` nem o instalador de produção. Se qualquer checagem falhar, o smoke para. Não substitua o hash esperado pelo valor do próprio manifesto.

Depois de baixar o artifact privado para `artifacts/native-smoke`, execute `node scripts/native-smoke-preflight.mjs artifacts/native-smoke <SHA256-do-log-da-CI>`. O processo abre apenas `RUMO-Smoke.exe`, verifica o banco novo e encerra. O arquivo de artifact e os dados gerados ficam em caminhos ignorados pelo Git. O preflight é uma condição necessária, não uma prova de que todos os comandos nativos funcionam.

Após preflight verde, no mesmo perfil isolado, use apenas fixtures criadas para o teste: Project `Smoke Project`, Task `Smoke Task`, PDF e PNG válidos gerados localmente. Valide anexar, abrir, revelar, fechar/reabrir, backup com attachments, alteração e restauração, `integrity_check`, backup antigo sintético sem attachments e rejeição de backup corrompido sem perda do estado atual. Depois valide close-to-tray, retorno, segunda instância, saída real, autostart (ligar, verificar e **desligar**), início minimizado, atalho global (registrar e liberar), notificação fictícia e dedupe, Focus com pause/resume/finish e persistência. Diferencie sucesso da API de notificação de toast visual observado. Nunca copie o banco ou um backup pessoal para esse perfil.

O teste Rust de Credential Manager usa uma identidade aleatória e somente segredos fictícios no namespace `RUMO-Test/google-calendar/…`; testa write/read/replace/delete e tenta cleanup também em falha. No runtime de smoke, Google e gateway utilizam `RUMO-Smoke-v180/…`. Não teste conta Google pessoal ou Pluggy Live. Sandbox Pluggy exige credenciais de teste legítimas e gateway separado; ausência delas deixa esse teste `NOT EXECUTED`.

Se Windows Application Control bloquear a execução do executável sem assinatura, registre o erro e pare. Não desative ou contorne a proteção. Mantenha o perfil de produção intocado e não declare smoke de runtime aprovado apenas porque build e testes Rust passaram na CI.
